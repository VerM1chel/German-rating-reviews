## Выводы

### LogisticRegression — лучший выбор по соотношению качество/время
LogisticRegression даёт F1 macro = 0.379 при обучении за 41 секунду. 
MLPClassifier показывает почти такой же результат (0.374), но обучается 4 часа. 
При ограниченном времени LogisticRegression — очевидный выбор.

### Качество зависит от размера и близости классов
Модель хорошо отделяет оценку 1 от остальных (F1 = 0.86), но внутри 
«не-1» работает на уровне случайного угадывания (F1 = 0.19–0.46). 
Это не дефект модели, а свойство данных: сильный дисбаланс (81% — оценка 1) 
и текстуальная близость соседних оценок (1↔2, 5↔6).

### XGBoost проигрывает даже с балансировкой классов
XGBoost с компенсацией дисбаланса (sample_weight) даёт F1 macro = 0.351 — 
всё равно ниже, чем у LogisticRegression (0.379). Значит, дело не только 
в дисбалансе. Вероятная причина — градиентный бустинг хуже работает 
с разреженными TF-IDF-признаками при 6 классах. Это гипотеза, 
требующая отдельной проверки.

### Grid Search не улучшил baseline
Поиск гиперпараметров для LogisticRegression дал F1 macro = 0.378 
против 0.379 у baseline. Причина: поиск шёл одновременно по гиперпараметрам 
и по пространству признаков, поэтому сравнение с baseline не совсем корректное. 
Чтобы честно оценить вклад гиперпараметров, нужно фиксировать признаки.

### Что можно улучшить в эксперименте
- Обучить MLP с class_weight, чтобы сравнение с LogisticRegression было честным.
- Попробовать бинарную постановку (1 vs не-1) или объединение редких классов — 
  проверить, не мешает ли модели избыточная детализация.
- Улучшить TF-IDF: ngram_range=(1,2), sublinear_tf=True.

### Что проверено и не требует изменений
- Стратификация при разбиении: проверена, разница долей классов между train 
  и test < 0.001. На датасете 439k строк не влияет на метрику.
